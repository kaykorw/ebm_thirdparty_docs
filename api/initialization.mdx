Initialization is the first fiscal step after RRA approves your equipment. Kayko’s `/initialize` routes provision the managed VSDC URL for your business.

After Enable EBM succeeds, Kayko stores `ebm_url` on the business record. Later transactional APIs never accept `ebm_url` in the JSON body, only tenant headers and your API key.

These routes accept the **internal** token (`X-API-Token`) or a business API key. Dashboard Enable EBM typically uses the internal token from Kayko dashboard. Definitions: [Glossary](/reference/glossary). Checklist: [Integration Checklist](/workflows/getting-started).

## Enable EBM

`POST /initialize/enable`

Provisions EBM for a business and returns `ebm_url` plus deployment tracking fields so you can poll status.

<ParamField body="business_code" type="string" required>
  Business code (`A–Z`, `0–9`, `_`, `-`), max 100.
</ParamField>

<ParamField body="redeploy" type="boolean">
  Force redeploy. Default `false`.
</ParamField>

The response includes `ebm_url`, `business_code`, `deployment_id`, and `status_url`. You can keep `ebm_url` for your own records. Kayko already stores it on the business, so later gateway calls do not need it in the body.

## Initialize device

`POST /initialize/init`

Kayko initializes the device with RRA and returns the **full** result envelope (`resultCd`, `resultMsg`, `resultDt`, `data`).

**Headers (required)**

| Header | Rule |
|--------|------|
| `x-tin` | 9-digit TIN |
| `x-branch-id` | 2-character branch ID (`00` = head office) |

**Body**

<ParamField body="device_serial_number" type="string" required>
  Device serial from RRA equipment registration.
</ParamField>

<ParamField body="business_code" type="string" required>
  Business code used to resolve `ebm_url` and validate TIN/branch.
</ParamField>

| Kayko input | Upstream field |
|-------------|----------------|
| `x-tin` | `tin` |
| `x-branch-id` | `bhfId` |
| `device_serial_number` | `dvcSrlNo` |

### Response `data.info` (inside the result envelope)

<ResponseField name="tin" type="string">Taxpayer TIN</ResponseField>
<ResponseField name="taxprNm" type="string">Registered business name</ResponseField>
<ResponseField name="bhfId" type="string">Branch ID</ResponseField>
<ResponseField name="bhfNm" type="string">Branch name</ResponseField>
<ResponseField name="dvcId" type="string">Server-assigned device ID</ResponseField>
<ResponseField name="intrlKey" type="string">Internal signing key</ResponseField>
<ResponseField name="signKey" type="string">Receipt signature key</ResponseField>
<ResponseField name="cmcKey" type="string">Communication key</ResponseField>

<Check>
  Call this **once** per device. Signing keys are separate from your business API key (`sk_…`).
</Check>
