Import lines originate in RRA customs for your TIN. Your job is to **list** them, map each declaration to a registered fiscal `item_code`, then **confirm** the line as approved or cancelled.

Send `x-tin` and `x-branch-id` on every route. Requires API key scope `import`. Confirm has **no quantity** in the body, quantities and weights come from the list response. After an approved confirm, Kayko posts stock-in asynchronously using that listed quantity.

Cross-flow: `GET /imports` → [`POST /items`](/api/items) if the product is new → `POST /imports/confirm` at branch `00` → automatic stock-in. See [Integration Checklist](/workflows/getting-started).

<Warning>
  Confirm must use head office `x-branch-id: 00`. Other branches receive `403` / `EBM_HEAD_OFFICE_REQUIRED`. List works for any allowed branch.
</Warning>

Confirm has **no quantity**. Quantity, weights, and currency amounts come from `GET /imports`. After an approved confirm, Kayko posts stock-in (`import`) asynchronously using that select quantity. Cancelled lines (`status: cancelled`) are skipped for stock.

## List imports

`GET /imports`

Send `x-last-request-date` (`YYYYMMDDHHmmss`). First sync: `20000101000000`.

Response: `{ message, data: ImportItem[] }`. Empty lists return `{ "message": "No import items found", "data": [] }`.

| Field | Description |
|-------|-------------|
| `task_code` | Customs task reference |
| `declaration_date` | Declaration date (`YYYYMMDD`) |
| `item_sequence` | Line sequence in the declaration |
| `declaration_number` | Declaration number |
| `hs_code` | HS tariff code |
| `item_name` | Declared name |
| `status` | e.g. `unsent`, `waiting`, `approved`, `cancelled` |
| `origin_country` / `export_country` | Country codes |
| `quantity` / `quantity_unit` | Declared quantity (used later for stock) |
| `package` / `packaging_unit` | Package count and unit |
| `gross_weight` / `net_weight` | Weights |
| `supplier` / `agent` | Names |
| `invoice_amount` / `invoice_currency` / `invoice_currency_rate` | Foreign-currency invoice |

Register the product with [Items](/api/items) **before** confirming, using the same `item_code` you will send on confirm.

## Confirm import

`POST /imports/confirm`

<ParamField body="task_code" type="string" required>Customs task code from the list response</ParamField>
<ParamField body="declaration_date" type="string" required>8 digits `YYYYMMDD`</ParamField>
<ParamField body="item_sequence" type="integer" required>Line sequence from the list response</ParamField>
<ParamField body="hs_code" type="string" required>HS code</ParamField>
<ParamField body="item_classification_code" type="string" required>Your 10-digit classification</ParamField>
<ParamField body="item_code" type="string" required>Your registered item code</ParamField>
<ParamField body="status" type="string" required>`approved` or `cancelled` (`canceled` is accepted)</ParamField>
<ParamField body="notes" type="string">Optional notes (max 400)</ParamField>

Success returns `{ message, data }` with the confirmed `task_code`, `declaration_date`, `item_sequence`, `hs_code`, `item_code`, `item_classification_code`, and `status`.

Do **not** POST a stock movement in the same request. Seed remaining quantity with `POST /stocks/master` so later import stock-in can update the ledger. See [Stock](/api/stock).
