An **item** is a product or service in your fiscal catalog. Every sale, purchase confirmation, import confirmation, and stock movement refers to an `item_code` that VSDC already knows. Register items at head office before you transact.

Requires a business API key with scope `items`. Send `x-tin` and `x-branch-id` on item routes.

---

## Item code format {#item-code-format}

Every registered product has a unique `item_code` (max 20 characters). The code embeds origin, product type, and units so RRA can validate sales, purchases, and stock.

### Structure

```
item_code = {origin_country}{item_type}{packaging_unit}{quantity_unit}{sequence}
             └──── 2 ────┘ └─── 1 ───┘ └───── 2 ─────┘ └───── 2 ────┘ └── 7 ──┘
                         Total: 14 characters (standard)
```

| Segment | Length | Request field | Example | Reference |
|---------|--------|---------------|---------|-----------|
| Country of origin | 2 | `origin_country` | `RW` | [Country codes](/reference/country-codes) |
| Product type | 1 | `item_type` | `2` (from label `finished_product`) | [Product type](/reference/enumerations#product-type) |
| Packaging unit | 2 | `packaging_unit` | `NT` | [Packaging units](/reference/enumerations#packaging-unit-full-list) |
| Quantity unit | 2 | `quantity_unit` | `U` | [Quantity units](/reference/enumerations#unit-of-quantity-full-list) |
| Sequence | 7 | Auto-increment | `0000001` | Unique per 7-character prefix |

<Note>
  `item_code` and `item_classification_code` are different. `item_classification_code` is the 10-digit RRA classification (what the product is). `item_code` is *your* unique product identifier.
</Note>

If you omit `item_code` on create, Kayko allocates the next sequence for that prefix. If you send one, the first 7 characters must equal `origin_country + item_type + packaging_unit + quantity_unit`.

### Annotated example

```
RW2NTU0000012
│││││└────── sequence (0000001, 0000012, …)
││││└─────── quantity_unit:  U  (Pieces)
│││└──────── packaging_unit: NT (Net)
││└───────── item_type:      2  (Finished Product)
└─────────── origin_country: RW (Rwanda)
```

### Generation rules

1. **Globally unique**, no two active items may share the same `item_code`.
2. **Prefix must match fields**, the first 7 characters must equal origin + type + packaging + quantity in the same request.
3. **Sequence increments per prefix**, for prefix `RW2NTU`, use `0000001`, then `0000002`, and so on.
4. **Never reuse**, retired items keep their codes.
5. **Immutable units**, changing `packaging_unit` or `quantity_unit` after registration requires a **new** `item_code`.

<Warning>
  A sale, purchase, or stock line that references an unregistered `item_code` fails. Register products first. Sales return `EBM_ITEM_NOT_REGISTERED` when the catalog is missing the code.
</Warning>

Item type **`service`** (upstream code `3`) still registers, but Kayko **does not** post stock movements after sales or purchases for services.
