Send `x-tin` and `x-branch-id` on every route below. Kayko resolves `ebm_url` from your business after Enable EBM, so you never put it in the JSON body.

Requires a business API key with scope `items`.

<Warning>
  Create, update, and deactivate must use head office `x-branch-id: 00`. Other branches receive `403` / `EBM_HEAD_OFFICE_REQUIRED`. List and get-by-code work for any allowed branch.
</Warning>

## Item code format {#item-code-format}

Every registered product has a unique `item_code` (max 20 characters). The code embeds origin, product type, and units so RRA can validate sales, purchases, and stock.

### Structure

```
item_code = {origin_country}{item_type}{packaging_unit}{quantity_unit}{sequence}
             └──── 2 ────┘ └─── 1 ───┘ └───── 2 ─────┘ └───── 2 ────┘ └── 7 ──┘
                         Total: 14 characters (standard)
```

| Segment | Length | Request field | Example | Reference |
|---------|--------|---------------|---------|-----------|
| Country of origin | 2 | `origin_country` | `RW` | [Country codes](/reference/country-codes) |
| Product type | 1 | `item_type` | `2` | [Product type](/reference/enumerations#product-type) |
| Packaging unit | 2 | `packaging_unit` | `NT` | [Packaging units](/reference/enumerations#packaging-unit-full-list) |
| Quantity unit | 2 | `quantity_unit` | `U` | [Quantity units](/reference/enumerations#unit-of-quantity-full-list) |
| Sequence | 7 | Auto-increment | `0000001` | Unique per 7-character prefix |

<Note>
  `item_code` and `item_classification_code` are different. `item_classification_code` is the 10-digit RRA classification (what the product is). `item_code` is *your* unique product identifier.
</Note>

If you omit `item_code` on create, Kayko allocates the next sequence for that prefix. If you send one, the first 7 characters must equal `origin_country + item_type + packaging_unit + quantity_unit`.

### Annotated example

```
RW2NTU0000012
│││││└────── sequence (0000001, 0000012, …)
││││└─────── quantity_unit:  U  (Pieces)
│││└──────── packaging_unit: NT (Net)
││└───────── item_type:      2  (Finished Product)
└─────────── origin_country: RW (Rwanda)
```

### Generation rules

1. **Globally unique** — no two active items may share the same `item_code`.
2. **Prefix must match fields** — the first 7 characters must equal origin + type + packaging + quantity in the same request.
3. **Sequence increments per prefix** — for prefix `RW2NTU`, use `0000001`, then `0000002`, and so on.
4. **Never reuse** — retired items keep their codes.
5. **Immutable units** — changing `packaging_unit` or `quantity_unit` after registration requires a **new** `item_code`.

<Warning>
  A sale, purchase, or stock line that references an unregistered `item_code` fails. Register products first. Sales return `EBM_ITEM_NOT_REGISTERED` when the catalog is missing the code.
</Warning>

Product type `3` is a **service**. Kayko still registers it, but it does **not** post stock movements after sales or purchases.

## Create item

`POST /items`

<ParamField body="item_classification_code" type="string" required>10-digit RRA classification</ParamField>
<ParamField body="item_type" type="string" required>`1` Raw Material, `2` Finished Product, `3` Service</ParamField>
<ParamField body="item_name" type="string" required>Product name (max 200)</ParamField>
<ParamField body="origin_country" type="string" required>ISO-style origin (e.g. `RW`)</ParamField>
<ParamField body="packaging_unit" type="string" required>Packaging code (e.g. `NT`)</ParamField>
<ParamField body="quantity_unit" type="string" required>Quantity code (e.g. `U`)</ParamField>
<ParamField body="tax_type" type="string" required>Tax category (`A`, `B`, `C`, `D`, `E`, `F`, `TT`)</ParamField>
<ParamField body="default_price" type="number" required>Default unit price (2 decimals)</ParamField>
<ParamField body="item_code" type="string">Optional. Omit to let Kayko allocate the next code for this prefix.</ParamField>
<ParamField body="standard_name" type="string">Standard / generic name</ParamField>
<ParamField body="barcode" type="string">Barcode</ParamField>
<ParamField body="batch_number" type="string">Batch number</ParamField>
<ParamField body="insurance_applicable" type="boolean">Defaults to `false`</ParamField>
<ParamField body="use" type="boolean">Active flag; defaults to `true`</ParamField>
<ParamField body="safety_quantity" type="number">Safety stock quantity</ParamField>
<ParamField body="additional_info" type="string">Extra info (max 7)</ParamField>
<ParamField body="group_price_1" type="number">Optional group prices 1–5</ParamField>

Registrar and modifier fields are set by Kayko.

<CodeGroup>

```bash cURL
curl -X POST "{{baseUrl}}/items" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk_live_YOUR_SECRET" \
  -H "x-tin: 100027060" \
  -H "x-branch-id: 00" \
  -d '{
    "item_classification_code": "8014160101",
    "item_type": "2",
    "item_name": "Coca Cola",
    "origin_country": "RW",
    "packaging_unit": "NT",
    "quantity_unit": "U",
    "tax_type": "B",
    "default_price": 118
  }'
```

```javascript JavaScript
await fetch(`${BASE_URL}/items`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${process.env.KAYKO_EBM_API_KEY}`,
    'x-tin': '100027060',
    'x-branch-id': '00',
  },
  body: JSON.stringify({
    item_classification_code: '8014160101',
    item_type: '2',
    item_name: 'Coca Cola',
    origin_country: 'RW',
    packaging_unit: 'NT',
    quantity_unit: 'U',
    tax_type: 'B',
    default_price: 118,
  }),
});
```

```json Payload
{
  "item_classification_code": "8014160101",
  "item_type": "2",
  "item_name": "Coca Cola",
  "origin_country": "RW",
  "packaging_unit": "NT",
  "quantity_unit": "U",
  "tax_type": "B",
  "default_price": 118,
  "insurance_applicable": false,
  "use": true
}
```

</CodeGroup>

Response:

```json
{
  "message": "success",
  "data": { "item_code": "RW2NTU0000001" }
}
```

## List items

`GET /items`

Send `x-last-request-date` (`YYYYMMDDHHmmss`). First sync: `20000101000000`.

<CodeGroup>

```bash cURL
curl -X GET "{{baseUrl}}/items" \
  -H "Authorization: Bearer sk_live_YOUR_SECRET" \
  -H "x-tin: 100027060" \
  -H "x-branch-id: 00" \
  -H "x-last-request-date: 20000101000000"
```

```javascript JavaScript
const data = await fetch(`${BASE_URL}/items`, {
  headers: {
    Authorization: `Bearer ${process.env.KAYKO_EBM_API_KEY}`,
    'x-tin': '100027060',
    'x-branch-id': '00',
    'x-last-request-date': '20000101000000',
  },
}).then((r) => r.json());
```

</CodeGroup>

Response shape: `{ message, data: Item[] }`. Each item uses snake_case (`item_code`, `item_name`, `tax_type`, `use`, …). Empty catalogs return `{ "message": "No items found", "data": [] }`.

## Get item

`GET /items/:item_code`

```bash
curl -X GET "{{baseUrl}}/items/RW2NTU0000001" \
  -H "Authorization: Bearer sk_live_YOUR_SECRET" \
  -H "x-tin: 100027060" \
  -H "x-branch-id: 00"
```

Missing items return `404` / `EBM_ITEM_NOT_FOUND`.

---

## Update item

`PUT /items/:item_code`

Same body as create, without `item_code` (it comes from the path). Head office required.

---

## Deactivate item

`DELETE /items/:item_code`

Sets `use` to false on VSDC. Head office required. The code is never recycled.

```bash
curl -X DELETE "{{baseUrl}}/items/RW2NTU0000001" \
  -H "Authorization: Bearer sk_live_YOUR_SECRET" \
  -H "x-tin: 100027060" \
  -H "x-branch-id: 00"
```

There is **no** item-composition endpoint on the Kayko gateway.
