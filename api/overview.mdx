## Authentication

Kayko integrations require a business API key on every request (except `/initialize/*`, which uses the internal `X-API-Token`):

```http
Authorization: Bearer sk_live_YOUR_SECRET
```

Or:

```http
x-api-key: sk_live_YOUR_SECRET
```

Generate the key in the dashboard: **Settings → Enable EBM → Generate API key**. Details: [API Keys & Authentication](/concepts/api-keys).

Prefer Kayko EBM gateway routes under `/ebm` (e.g. `POST /initialize/init`, `POST /customers/select`) over calling VSDC WAR paths such as `/initializer/selectInitInfo` directly.

## Base URL

Use the **environment dropdown** at the top of any endpoint page to switch between:

| Environment | When to use |
|-------------|-------------|
| **Local EBM** | Kayko EBM gateway (preferred for live EBM routes) |
| **Production VSDC** | Direct hosted VSDC |
| **Local VSDC** | Self-hosted WAR |

Code examples use `{{baseUrl}}` and update when you change the environment.

## Standard response

```json
{
  "resultCd": "000",
  "resultMsg": "It is succeeded",
  "resultDt": "20260303145619",
  "data": null
}
```

- `resultCd: "000"` → success
- `resultCd: "001"` → no new data (sync endpoints only- not an error)
- Anything else → see [Response Codes](/reference/response-codes)

## Code example pattern

Every endpoint in this reference follows the same multi-language pattern:

<CodeGroup>

```bash cURL
curl -X POST "{{baseUrl}}/endpoint" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk_live_YOUR_SECRET" \
  -d '{ ... }'
```

```javascript JavaScript
const res = await fetch(`${BASE_URL}/endpoint`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${process.env.KAYKO_EBM_API_KEY}`,
  },
  body: JSON.stringify({ ... }),
}).then(r => r.json());
```

```php PHP
<?php
$response = vsdcPost('/endpoint', [ ... ]); // include Authorization: Bearer in your HTTP client
```


</CodeGroup>
