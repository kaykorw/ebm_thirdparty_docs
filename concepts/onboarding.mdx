## 1.1 What Kayko EBM is

**Kayko EBM** is the API gateway that lets private CIS/ERP applications send and receive data (sales, purchases, receipts, stock, and more) with the **RRA EBM 2.1** tax infrastructure. Your software calls Kayko EBM only, Kayko handles the connection to RRA.

## 1.2 Environments

| Type | Description |
|------|-------------|
| **Production** | Live environment. Sends/receives data to the RRA EBM API **production** server. All receipts have legal effect. |
| **Test** | Development environment. Sends/receives test data to the RRA EBM API **test** server. Used during integration and RRA certification. |

### Technical stack

| Property | Value |
|----------|-------|
| Access | Kayko EBM HTTP API |
| API style | REST |
| Data format | JSON |
| Authentication | Business API key (`Authorization: Bearer sk_…`) |
| Supported languages | All (via HTTPS) |

<Note>
  EBM 2.1 server addresses (production and test) are assigned by RRA upon approval. Integrators always call the **Kayko EBM** base URL for their environment, see [Introduction](/introduction#base-url).
</Note>

## 2.1 Application process

To use Kayko EBM, a taxpayer must complete the following:

1. **Register on MyRRA**, join as a site member at RRA's taxpayer portal
2. **Apply for EBM 2.1 service**, submit a service request after MyRRA membership
3. **Register equipment**, submit equipment use application; RRA assigns a device serial number (`dvcSrlNo` / `device_serial_number`)
4. **Receive RRA approval**, RRA approves the EBM service request
5. **Enable EBM in Kayko**, Business dashboard → **Settings → Enable EBM**, then **generate an API key**. See [API Keys & Authentication](/concepts/api-keys)
6. **Initialize the device**, call `POST /initialize/init` with TIN, branch ID, device serial number, and `ebm_url`
7. **Receive keys**, Kayko EBM verifies the device with RRA and returns `intrlKey`, `signKey`, `cmcKey`

<Warning>
  Initialization is a **one-time** operation per device. Do not re-initialize unless RRA instructs you to. Your Kayko API key is separate from these device signing keys and must be sent on every HTTP request (except internal `/initialize/*` routes).
</Warning>

## 2.2 Technical policies (mandatory)

These four policies are **enforced** and must be followed by every integration:

### Policy 1, Call Kayko EBM only

Your CIS/ERP must call the **Kayko EBM gateway**. Do not call RRA EBM servers directly.

### Policy 2, Authenticate every request

Send a valid business API key (`Authorization: Bearer sk_…` or `x-api-key`) on customer, constants, sales, and other scoped routes. Initialization uses the internal token when Core360 enables EBM.

### Policy 3, Manage `lastReqDt` cursors

When pulling data, send the **date/time of your last successful sync** (`lastReqDt`). After each successful pull, update the cursor to the `resultDt` from the response. Your CIS is responsible for storing and managing these timestamps per endpoint and per branch.

See [Data Synchronization](/concepts/data-sync) for implementation details.

### Policy 4, 24-hour offline receipt limit

> If there is no internet connection for **24 hours** after a receipt signature and internal data are issued, the service **stops issuing receipt numbers**.

This means:
- Plan for connectivity outages in your POS/ERP architecture
- Queue transactions locally when offline
- Reconnect and sync within 24 hours
- Use `POST /sales/resend` if VSDC signed the sale but Kayko could not persist it (`EBM_SALE_PERSIST_FAILED`)

## 2.3 Sample integration code

Code examples in **cURL, JavaScript, and PHP** are provided on each endpoint page. Authenticate with your API key:

```
POST {{baseUrl}}/customers/select
Authorization: Bearer sk_live_YOUR_SECRET
Content-Type: application/json

{
  "tin": "100027060",
  "branch_id": "00",
  "customer_tin": "100004527",
  "ebm_url": "http://localhost:8080/rra/ACME01/"
}
```

## Head office vs branch roles

Several operations are restricted to the **head office** (`bhfId: "00"`):

| Operation | Head office only? |
|-----------|-------------------|
| Save items | Yes |
| Save item composition | Yes |
| Get/select imported items | Yes |
| Update imported items | Yes |
| Get purchase transactions | Yes |
| Save purchase confirmations | Yes |
| Save stock in/out | No (any branch) |
| Save stock count | No (any branch) |
| Save branch customers/users | No |
| Save sales | No |

## Pharmacy-specific

`/branches/saveBrancheInsurances` is documented by RRA as **pharmacy-only**. Insurance fields on sales line items (`isrccCd`, `isrccNm`, `isrcRt`, `isrcAmt`) apply when `isrcAplcbYn: "Y"` on the item.
