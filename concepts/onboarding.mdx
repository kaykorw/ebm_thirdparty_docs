## 1.1 What VSDC is

**Virtual Sales Data Controller (VSDC)** is a communication module that lets private CIS/ERP applications send and receive data (sales, purchases, receipts, stock, etc.) to and from the **RRA EBM 2.1 API server**. It is the bridge between your business software and RRA's tax infrastructure.

## 1.2 Environments

| Type | Description |
|------|-------------|
| **Production VSDC** | Live environment. Sends/receives data to the RRA EBM API **production** server. All receipts have legal effect. |
| **Test VSDC** | Development environment. Sends/receives test data to the RRA EBM API **test** server. Used during integration and RRA certification. |

### Technical stack (per RRA spec)

| Property | Value |
|----------|-------|
| Distributed package | WAR file |
| API style | REST |
| Data format | JSON |
| Supported web servers | Tomcat, Jetty, Apache HTTP Server |
| Supported OS | Windows 10+, Linux, Unix |
| Supported languages | All (via web services) |

<Note>
  EBM 2.1 API server addresses (production and test) and VSDC request form URLs are assigned by RRA upon approval. Kayko-hosted deployments use `https://vsdc.kayko.rw/rra-2.1.2.3.8`.
</Note>

## 2.1 Application process

To use VSDC, a taxpayer must complete the following:

1. **Register on MyRRA**- join as a site member at RRA's taxpayer portal
2. **Apply for EBM 2.1 / VSDC service**- submit a service request after MyRRA membership
3. **Register equipment**- submit equipment use application; RRA assigns a device serial number (`dvcSrlNo`)
4. **Receive RRA approval**- RRA approves the VSDC service request
5. **Deploy the WAR**- RRA provides a WAR file for self-hosted deployments, or use a managed provider (e.g. Kayko)
6. **Enable EBM in Kayko**- Business dashboard → **Settings → Enable EBM**, then **generate an API key**. See [API Keys & Authentication](/concepts/api-keys)
7. **Initialize the device**- call `POST /initializer/selectInitInfo` with TIN, branch ID, device serial number, and your API key header
8. **Receive keys**- VSDC verifies the device with RRA and stores `intrlKey`, `signKey`, `cmcKey`

<Warning>
  Initialization is a **one-time** operation per device. Do not re-initialize unless RRA instructs you to. Your Kayko API key is separate from these device signing keys and must be sent on every HTTP request.
</Warning>

## 2.2 Technical policies (mandatory)

These four policies are **enforced by VSDC** and must be followed by every integration:

### Policy 1- VSDC must be running locally

For self-hosted deployments, the VSDC WAR must be deployed and running on your web server before any API calls. Your CIS/ERP calls VSDC locally; VSDC calls RRA.

### Policy 2- All EBM communication goes through VSDC

Your application must **never** call the RRA EBM API directly. All data exchange is via VSDC web service methods.

### Policy 3- Manage `lastReqDt` cursors

When pulling data from RRA, you must send the **date/time of your last successful sync** (`lastReqDt`). After each successful pull, update the cursor to the `resultDt` from the response. Your CIS is responsible for storing and managing these timestamps per endpoint and per branch.

See [Data Synchronization](/concepts/data-sync) for implementation details.

### Policy 4- 24-hour offline receipt limit

> If there is no internet connection for **24 hours** after VSDC issues a receipt signature and internal data, VSDC **stops issuing receipt numbers**.

This means:
- Plan for connectivity outages in your POS/ERP architecture
- Queue transactions locally when offline
- Reconnect and sync within 24 hours
- Use `/trnsSales/resendSales` for failed submissions that were processed locally

## 2.3 Sample integration code

Code examples in **cURL, JavaScript, and PHP** are provided on each endpoint page. Authenticate Kayko-hosted calls with your API key:

```
POST http://localhost:8080/initializer/selectInitInfo
Authorization: Bearer sk_live_YOUR_SECRET
Content-Type: application/json

{
  "tin": "999993204",
  "bhfId": "00",
  "dvcSrlNo": "dvc999993204"
}
```

## Head office vs branch roles

Several operations are restricted to the **head office** (`bhfId: "00"`):

| Operation | Head office only? |
|-----------|-------------------|
| Save items | Yes |
| Save item composition | Yes |
| Get/select imported items | Yes |
| Update imported items | Yes |
| Get purchase transactions | Yes |
| Save purchase confirmations | Yes |
| Save stock in/out | No (any branch) |
| Save stock master | No (any branch) |
| Save branch customers/users | No |
| Save sales | No |

## Pharmacy-specific

`/branches/saveBrancheInsurances` is documented by RRA as **pharmacy-only**. Insurance fields on sales line items (`isrccCd`, `isrccNm`, `isrcRt`, `isrcAmt`) apply when `isrcAplcbYn: "Y"` on the item.
