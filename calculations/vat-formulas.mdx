Rwanda EBM uses tax-inclusive prices. Kayko maps your snake_case fields (`tax_type`, `taxable_amount`, `tax_amount`) to VSDC `taxTyCd` / `taxblAmt` / `taxAmt`.

You can omit line and header tax amounts on Kayko requests. Kayko computes them. Live `saveSales` always includes **`taxRtF` (18)** and **`taxRtTt` (0 or 3)**. Omitting those keys returns `910` (incorrect tax rates).

Tourism tax and VAT on fuel are documented in [Tourism Tax and VAT on Fuel](/calculations/tourism-and-fuel).

## Tax categories

| Code | Name | Rate | Line `tax_amount` |
|------|------|------|-------------------|
| `A` | A-EX (Exempt) | 0% | `0` |
| `B` | B-18% (Standard VAT) | 18% | `taxable_amount × 18 / 118` |
| `C` | C (Zero-rated) | 0% | `0` |
| `D` | D (Non-VAT) | 0% | `0` |
| `E` | E (reserved) | 0% | `0` |
| `F` | F (VAT on Fuel) | 18% | Same as B: `taxable_amount × 18 / 118` |
| `TT` | TT (Tourism tax rate) | 3% | **Not a sale line `tax_type`.** Tourism uses `use_tourism_tax` and `ttAmt`. |

Most goods use **`B`**. Fuel (gasoline/diesel) uses **`F`**. Tourism is additive on a VAT line, not a replacement tax type.

Live rates: `GET /constants/taxes` (`code`, `name`, `rate`).

## Why 18/118 and not 18%?

Category B (and fuel F) prices are **tax-inclusive**. The customer pays one total that already includes VAT. You **extract** the VAT portion rather than adding 18% on top.

If the tax-inclusive amount is **T**, the VAT component **V** is:

```
V = T × (rate / (100 + rate))
```

For 18% VAT:

```
tax_amount = taxable_amount × 18 / 118
```

### Derivation

Let **T** = tax-inclusive total (what `taxable_amount` stores for category B).

```
T = netPrice + VAT
VAT = netPrice × 0.18
T = netPrice × 1.18
netPrice = T / 1.18 = T × 100/118

VAT = T − netPrice
    = T − (T × 100/118)
    = T × (1 − 100/118)
    = T × 18/118
```

<Note>
  Do **not** calculate `tax_amount = taxable_amount × 0.18`. That treats the amount as tax-exclusive and VSDC rejects the invoice (`910`).
</Note>

## Worked example, single line, category B

Selling **2 units** at **1,000 RWF** each (tax-inclusive):

| Step | Kayko field | Formula | Result |
|------|-------------|---------|--------|
| 1 | `price` | Unit price (inclusive) | 1,000.00 |
| 2 | `quantity` | Quantity | 2 |
| 3 | `supply_amount` | `price × quantity` | 2,000.00 |
| 4 | `taxable_amount` | Same as supply (no discount) | 2,000.00 |
| 5 | `tax_amount` | `2,000 × 18 / 118` | **305.08** |
| 6 | `total_amount` | Same as taxable | 2,000.00 |

Verification: `2,000 × 18 ÷ 118 = 305.0847…` → rounded to **305.08**.

### Invoice header for this sale

Kayko field → VSDC field:

| Kayko | VSDC | Value |
|-------|------|-------|
| `taxable_amount_b` | `taxblAmtB` | 2,000.00 |
| (computed) | `taxRtB` | 18 |
| `tax_amount_b` | `taxAmtB` | 305.08 |
| (computed) | `taxRtF` | 18 |
| (computed) | `taxRtTt` | 0 (or 3 if the TIN is tourism-registered) |
| `taxable_amount_f` / `tt` | `taxblAmtF` / `Tt` | 0 |
| `total_taxable_amount` | `totTaxblAmt` | 2,000.00 |
| `total_tax_amount` | `totTaxAmt` | 305.08 |
| `total_amount` | `totAmt` | 2,000.00 |

Always include `taxRtF` and `taxRtTt` even when fuel/tourism amounts are 0.

## Categories A, C, D, E, zero VAT

```
tax_amount      = 0
taxable_amount  = supply_amount − total_discount_amount
total_amount    = taxable_amount
```

Set `tax_type` correctly (`A`, `C`, `D`, or `E`).

## JavaScript helper

```javascript
function extractVat(taxInclusiveAmount, rate = 18) {
  return Math.round((taxInclusiveAmount * rate) / (100 + rate) * 100) / 100;
}

// extractVat(2000) → 305.08
// extractVat(8474.58, 3) → 246.83  (tourism on VAT-exclusive base)
```

## Common mistakes

| Mistake | Wrong result | Correct approach |
|---------|--------------|------------------|
| `tax_amount = taxable_amount × 0.18` | 360.00 on 2,000 | Use `× 18/118` → 305.08 |
| Rounding only at header | Header ≠ sum of lines | Round each line first, then sum |
| Line `tax_type: "B"` but amounts in A | Validation error | B lines → `taxable_amount_b` |
| Integer amounts (`305` not `305.08`) | Error 910 | Always 2 decimal places |
| Treating `F` as tourism or sending `tax_type: TT` | Error 910 / `EBM_TAX_TYPE_TT_UNSUPPORTED` | Fuel is `F` at 18%. Tourism is `use_tourism_tax` + `ttAmt` |
| Omitting `taxRtF` / `taxRtTt` | Error 910 (“incorrect tax rates”) | Kayko always sends them; do not strip header rates |
| Normal sale `original_invoice_no` = `invoice_no` | Error 910 | Leave it off; Kayko sends `orgInvcNo: 0` |
