Rwanda EBM uses tax-inclusive prices. Kayko maps your snake_case fields (`tax_type`, `taxable_amount`, `tax_amount`) to VSDC `taxTyCd` / `taxblAmt` / `taxAmt`. Live devices require header **rates** for A–D **and** E, F, and TT.

You can omit line and header tax amounts on Kayko requests. Kayko computes them and always sends rates as JSON **numbers with two decimals** (NUMBER 7,2), e.g. `"taxRtF":3.00` not `3` or `"3"`.

## Tax categories

| Code | Name | Rate | Line `tax_amount` |
|------|------|------|-------------------|
| `A` | A-EX (Exempt) | 0% | `0` |
| `B` | B-18% (Standard VAT) | 18% | `taxable_amount × 18 / 118` |
| `C` | C (Zero-rated) | 0% | `0` |
| `D` | D (Non-VAT) | 0% | `0` |
| `E` | E (reserved) | 0% | `0` |
| `F` | F (Tourism tax) | 3% | `taxable_amount × 3 / 103` when the line uses `F` |
| `TT` | TT | 3% | Same extraction when the line uses `TT` |

Most goods use **`B`**. Spec PDF v1.0.5 documents header tax types A–D; current VSDC firmware also expects tourism header keys **`taxRtF`** and **`taxRtTt`** on every sale. Kayko’s default for non-tourism TINs is to send those keys as JSON **`null`**. Tourism sales (`tourism_tax: true`) use catalog rates (usually 3). Overrides are configured per TIN via [`PUT /codes/tourism`](/api/codes). Forcing `3.00` on a non-tourism device commonly returns `910` (“Wrong Tourism Tax rate”).

Live rates: `GET /constants/taxes` (`code`, `name`, `rate`).

## Why 18/118 and not 18%?

Category B prices are **tax-inclusive**. The customer pays one total that already includes VAT. You **extract** the VAT portion rather than adding 18% on top.

If the tax-inclusive amount is **T**, the VAT component **V** is:

```
V = T × (rate / (100 + rate))
```

For 18% VAT:

```
tax_amount = taxable_amount × 18 / 118
```

### Derivation

Let **T** = tax-inclusive total (what `taxable_amount` stores for category B).

```
T = netPrice + VAT
VAT = netPrice × 0.18
T = netPrice × 1.18
netPrice = T / 1.18 = T × 100/118

VAT = T − netPrice
    = T − (T × 100/118)
    = T × (1 − 100/118)
    = T × 18/118
```

<Note>
  Do **not** calculate `tax_amount = taxable_amount × 0.18`. That treats the amount as tax-exclusive and VSDC rejects the invoice (`910`).
</Note>

## Worked example, single line, category B

Selling **2 units** at **1,000 RWF** each (tax-inclusive):

| Step | Kayko field | Formula | Result |
|------|-------------|---------|--------|
| 1 | `price` | Unit price (inclusive) | 1,000.00 |
| 2 | `quantity` | Quantity | 2 |
| 3 | `supply_amount` | `price × quantity` | 2,000.00 |
| 4 | `taxable_amount` | Same as supply (no discount) | 2,000.00 |
| 5 | `tax_amount` | `2,000 × 18 / 118` | **305.08** |
| 6 | `total_amount` | Same as taxable | 2,000.00 |

Verification: `2,000 × 18 ÷ 118 = 305.0847…` → rounded to **305.08**.

### Invoice header for this sale

Kayko field → VSDC field:

| Kayko | VSDC | Value |
|-------|------|-------|
| `taxable_amount_b` | `taxblAmtB` | 2,000.00 |
| (computed) | `taxRtB` | 18.00 |
| `tax_amount_b` | `taxAmtB` | 305.08 |
| `taxable_amount_a/c/d/e/f/tt` | `taxblAmt*` | 0 |
| `total_taxable_amount` | `totTaxblAmt` | 2,000.00 |
| `total_tax_amount` | `totTaxAmt` | 305.08 |
| `total_amount` | `totAmt` | 2,000.00 |

Always include rates E/F/TT even when amounts are 0.

## Categories A, C, D, E, zero VAT

```
tax_amount      = 0
taxable_amount  = supply_amount − total_discount_amount
total_amount    = taxable_amount
```

Set `tax_type` correctly (`A`, `C`, `D`, or `E`).

## Multi-category invoice

One **exempt** line (A) for 5,000 RWF and one **VAT** line (B) for 2,000 RWF:

```json
  "total_amount": 7000

```

## JavaScript helper

```javascript
function extractVat(taxInclusiveAmount, rate = 18) {
  return Math.round((taxInclusiveAmount * rate) / (100 + rate) * 100) / 100;
}

// extractVat(2000) → 305.08
// extractVat(2000, 3) → 58.25  (tourism F / TT)
```

## Common mistakes

| Mistake | Wrong result | Correct approach |
|---------|--------------|------------------|
| `tax_amount = taxable_amount × 0.18` | 360.00 on 2,000 | Use `× 18/118` → 305.08 |
| Rounding only at header | Header ≠ sum of lines | Round each line first, then sum |
| Line `tax_type: "B"` but amounts in A | Validation error | B lines → `taxable_amount_b` |
| Integer amounts (`305` not `305.08`) | Error 910 | Always 2 decimal places |
| Missing tourism header keys or wrong programmed rate | Error 910 on live devices | Use Kayko’s tourism strategy / `PUT /codes/tourism`; do not hard-code `3.00` for every TIN |
| Normal sale `original_invoice_no` = `invoice_no` | Error 910 | Leave it off; Kayko sends `orgInvcNo: 0` |
