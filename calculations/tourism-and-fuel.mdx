RRA added two separate taxes on VSDC 2.0. **They are not the same field.**

| | Tourism tax | VAT on fuel |
|---|---|---|
| Who | Hospitality / tourism TINs | Fuel dealers selling gasoline or diesel |
| Line `tax_type` | Keep VAT `A`–`D` (usually `B`) | `F` (18% VAT on fuel) |
| How a line is flagged | Item `use_tourism_tax: true` (`useTTaxYn: Y`) or sale line `use_tourism_tax: true` | Fuel catalog item + `tax_type: F` |
| Header rates | `taxRtTt` is `3` if the TIN is tourism-registered, else `0` | `taxRtF` is always `18` |
| Amounts | Line `ttAmt`, header `taxblAmtTt` / `taxAmtTt` / `totalTTAmt` | Header `taxblAmtF` / `taxAmtF` from `F` lines |

Do **not** send `tax_type: "TT"` on a sale line. Do **not** treat `F` as tourism.

## Tourism tax

Only TINs whose business category is hospitality / tourism may register tourism-taxable items (`EBM_TOURISM_TAX_TIN_REQUIRED` otherwise).

### Register the item

On [`POST /items`](/api/items) set `use_tourism_tax: true` and keep `tax_type: "B"` (or `A` / `C` / `D` as appropriate). Kayko sends `useTTaxYn: Y` to VSDC.

### Sell it

Keep the line `tax_type` as the VAT category. Set `use_tourism_tax: true` only if the catalog did not already carry `useTTaxYn: Y`.

Kayko computes tourism from the **VAT-exclusive** supply (RRA VSDC 2.0 formula):

```
ttTaxblAmt = ROUND(supply_amount × 100 / 118, 2)
ttAmt      = ROUND(ttTaxblAmt × 3 / 103, 2)
```

Example: `supply_amount` 10,000.00 → taxable 8,474.58 → tourism tax **246.83**.

Header fields Kayko always sends:

| VSDC | Meaning |
|------|---------|
| `taxRtTt` | `3` for tourism-registered TINs, otherwise `0` |
| `taxblAmtTt` | Sum of `ttTaxblAmt` for tourism lines |
| `taxAmtTt` / `totalTTAmt` | Sum of line `ttAmt` |
| line `ttAmt` | Per-line tourism amount (`0` when the line is not tourism-taxable) |

Tourism amounts are **in addition to** VAT. They are **not** added into `totTaxblAmt` (the goods are already in bucket A–D).

### Printed invoice

`POST /sales` returns `print.tourism`:

| Field | Meaning |
|-------|---------|
| `registered` | This TIN is tourism-tax registered |
| `has_taxable_items` | At least one line had tourism tax |
| `total_tt` | Receipt total tourism tax |
| `disclaimer` | `"This is the official tax invoice with no tourism tax."` when registered but no tourism lines; otherwise `null` |

Print the disclaimer on tourism-registered invoices that have no tourism-taxable items.

## VAT on fuel (gasoline and diesel)

Fuel products are **RRA-managed**. Do not create them with `POST /items`.

### Catalog

1. `GET /items/fuel` — pull RRA reference products (`items/reference/getFuelProducts`). Needs `x-last-request-date`.
2. `POST /items/fuel/sync` — write each product to VSDC with `saveItems`, `taxTyCd: F`, and RRA’s `itemCd` (for example `RW2TYXL1000001`).
3. `POST /items/fuel/rrp` — report an RRP change (`saveRrpChangeHistory`). Kayko updates `dftPrc` only after VSDC succeeds.

Create / update / deactivate of fuel items returns `EBM_FUEL_ITEM_READONLY`. Item list rows include `is_fuel` and `system_managed`.

Known fuel classifications: `1510150500` (diesel) and `1510150600` (gasoline). Packaging is typically `TY` (tank), quantity `L` (litre).

### Sell fuel

| Field | Rule |
|-------|------|
| `tax_type` | `F` (18% VAT, same 18/118 extraction as `B`) |
| `sale_purpose` | Required: `FOR_RESELL` or `FOR_CONSUMPTION` |
| `rrp` | Required on the line (or taken from catalog `default_price`) |
| `price` | ≥ RRP and at most RRP + **15** RWF |
| `regulated_discount` | Optional 0–120 (`prftDcAmt`). Deducted from taxable amount |
| Normal discounts | Not allowed (`discount_rate` / `discount_amount` / `total_discount_amount` must be 0) |

Kayko sends `salePurposeCd` (`01` resell, `02` consumption) only when the invoice contains fuel lines.

### Header for a Coca Cola sale (no fuel, no tourism)

A normal `tax_type: B` invoice still includes the new keys, with zero fuel/tourism amounts:

| VSDC | Value |
|------|-------|
| `taxRtB` | 18 |
| `taxRtF` | 18 |
| `taxRtTt` | 0 (unless the TIN is tourism-registered, then 3) |
| `taxblAmtF` / `taxAmtF` | 0 |
| `taxblAmtTt` / `taxAmtTt` / `totalTTAmt` | 0 |

Omitting `taxRtF` / `taxRtTt` is what live devices reject as **incorrect tax rates** (`910`).
