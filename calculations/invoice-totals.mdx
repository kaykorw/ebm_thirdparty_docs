Kayko requires **duplicate accounting**, every amount appears on the line and again on the header. Header values must be the **exact sum** of their line counterparts. You may omit header fields on `POST /sales` and `POST /purchases/confirm`; Kayko computes them. If you send them, they must match or VSDC returns `910`.

On the wire to VSDC, Kayko sends rates A–D plus live extensions **E**, **F**, and **TT**. Tourism rates **F/TT** follow the per-TIN strategy (null, catalog, or override), not a fixed `3.00` for every business. Configure via [`PUT /codes/tourism`](/api/codes).

## Header tax fields

| Kayko field | VSDC field | Meaning |
|-------------|------------|---------|
| `taxable_amount_a` … `_d`, `_e`, `_f`, `_tt` | `taxblAmtA`–`D`, `E`, `F`, `Tt` | Sum of `taxable_amount` for lines with that `tax_type` |
| (computed) | `taxRtA`–`D`, `E`, `F`, `Tt` | 0, 18, 0, 0, 0, 3, 3 |
| `tax_amount_a` … `_tt` | `taxAmt*` | Sum of `tax_amount` for that category |
| `total_taxable_amount` | `totTaxblAmt` | Sum of all taxable buckets |
| `total_tax_amount` | `totTaxAmt` | Sum of all tax buckets |
| `total_amount` | `totAmt` | Sum of all line `total_amount` |
| `item_count` | `totItemCnt` | Number of lines |

## Aggregation formulas

```
taxable_amount_X = Σ line.taxable_amount  where line.tax_type = X
tax_amount_X     = Σ line.tax_amount      where line.tax_type = X

total_taxable_amount = A+B+C+D+E+F+TT
total_tax_amount     = A+B+C+D+E+F+TT
total_amount         = Σ line.total_amount
```

<Note>
  Round each line's `tax_amount` to 2 decimal places **before** summing. Do not sum unrounded values and round only the header.
</Note>

## Worked example, two-line purchase

**Line 1** (`tax_type: "B"`): taxable 7,000.00, tax 1,067.80, total 7,000.00

**Line 2** (`tax_type: "B"`): taxable 1,000.00, tax 152.54, total 1,000.00

| Field | Formula | Value |
|-------|---------|-------|
| `taxable_amount_b` | 7000 + 1000 | 8,000.00 |
| `tax_amount_b` | 1067.80 + 152.54 | 1,220.34 |
| `total_taxable_amount` | 8000 | 8,000.00 |
| `total_tax_amount` | 1220.34 | 1,220.34 |
| `total_amount` | 7000 + 1000 | 8,000.00 |
| `item_count` | 2 lines | 2 |

Supplier-pulled purchases may have `price × quantity ≠ taxable_amount`. Confirm with internally consistent amounts.

## Consistency checks

```
assert taxable_amount_b === sum(lines.filter(l => l.tax_type === 'B').map(l => l.taxable_amount))
assert tax_amount_b     === sum(lines.filter(l => l.tax_type === 'B').map(l => l.tax_amount))
assert total_amount     === sum(lines.map(l => l.total_amount))
assert item_count       === items.length
```

## What happens when totals mismatch

| Symptom | Likely cause |
|---------|--------------|
| VSDC `910` | Header tax ≠ sum of line tax |
| VSDC `910` | `total_amount` ≠ sum of line totals |
| VSDC `910` | `item_count` ≠ `items.length` |
| VSDC `910` | Line `tax_type: "B"` but amounts in the wrong header bucket |
| VSDC `910` | Missing/invalid tourism header rates or totals mismatch (Kayko applies tourism strategy; configure `/codes/tourism` if needed) |
