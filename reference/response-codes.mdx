## Gateway HTTP errors

These are Kayko responses (`{ status, message, error }`), not VSDC result codes.

VSDC failures from `/ebm` routes are remapped to:

```json
{
  "status": "910",
  "message": "…",
  "date": "20260820184713"
}
```

`status` is the VSDC result code (`resultCd`). HTTP status follows the code family (4xx/5xx).

| HTTP | `error` | Meaning |
|------|---------|---------|
| 403 | `EBM_HEAD_OFFICE_REQUIRED` | Item write, import confirm, and purchase confirm must use `x-branch-id: 00` |
| 400 | `EBM_ITEM_NOT_REGISTERED` | Sale/purchase line `item_code` is not in the catalog |
| 400 | `EBM_FUEL_ITEM_READONLY` | Create/update/deactivate of RRA fuel items. Use `POST /items/fuel/sync` and `POST /items/fuel/rrp` |
| 400 | `EBM_SALE_PURPOSE_REQUIRED` | Fuel sale missing `sale_purpose` |
| 400 | `EBM_TAX_TYPE_TT_UNSUPPORTED` | Sale line `tax_type: TT`. Use `use_tourism_tax` instead |
| 400 | `EBM_TOURISM_TAX_TIN_REQUIRED` | `use_tourism_tax` on a TIN that is not hospitality/tourism |
| 404 | `EBM_ITEM_NOT_FOUND` | `GET/PUT/DELETE /items/:item_code` |
| 503 | `EBM_SALE_PERSIST_FAILED` | VSDC signed the sale (`000`) but Kayko could not persist it. **Do not change `invoice_no`.** Retry `POST /sales/resend` with the signature fields in the body |
| 503 | `EBM_SALES_STORE_UNAVAILABLE` | Local store is down; Kayko did not call VSDC |
| 429 | `API_KEY_RATE_LIMITED` | Per-key hourly limit |

Auth errors (`API_KEY_*`) are listed on [API Keys](/concepts/api-keys).

## Success codes

| Code | Message | Action |
|------|---------|--------|
| `000` | It is succeeded | Proceed- operation completed successfully |
| `001` | There is no search result | Not an error- no new data since your `lastReqDt`. Update your sync cursor and continue. |

## Client errors (881–899)

These indicate issues with your request data or client configuration.

| Code | Description | How to fix |
|------|-------------|------------|
| `881` | Purchase is mandatory | Provide `prcOrdCd` for business customers |
| `882` | Purchase code is invalid | Verify `prcOrdCd` with the supplier |
| `883` | Purchase already used | This purchase was already confirmed- skip it |
| `884` | Invalid customer TIN | Validate TIN via `GET /customers` first |
| `891` | Error creating Request URL | Check your Kayko EBM base URL and path |
| `892` | Error creating Request Header | Check Content-Type and headers |
| `893` | Error creating Request Body | Validate JSON structure and required fields |
| `894` | Server communication error | Check network connectivity to Kayko EBM / RRA |
| `895` | Unallowed Request Method | Gateway uses `GET` or `POST` as documented; do not call raw VSDC paths |
| `896` | Request Status error | Check HTTP status and retry |
| `899` | Client error | General client-side failure- check logs |

## Server errors (900–999)

These indicate issues on the Kayko EBM or RRA server side.

| Code | Description | How to fix |
|------|-------------|------------|
| `900` | No Header information | Ensure `Content-Type: application/json` header is set |
| `901` | Not valid device | Re-initialize with correct `dvcSrlNo` |
| `902` | Device already installed | Device was already initialized- skip re-init |
| `903` | Only a registered EBM device can be verified | Use a registered EBM device |
| `910` | Request parameter error | Totals mismatch, wrong types, **normal sale `orgInvcNo` not `0`**, missing or incorrect `taxRtF` / `taxRtTt`, or other field validation. Kayko maps snake_case for you, omit optional totals unless you can match line math. See [Tourism Tax and VAT on Fuel](/calculations/tourism-and-fuel). |
| `911` | No request full text | Request body is empty |
| `912` | Request Method error | Use the documented Kayko method (`GET` / `POST` / `PUT` / `DELETE`) |
| `921` | Sales data cannot be received | Invoice data conflict- check invoice numbers |
| `922` | Invoice before sales data | Submit sales transaction before invoice |
| `990` | Max views exceeded | Reduce pagination range |
| `991` | Registration error | Data validation failed on create |
| `992` | Modification error | Data validation failed on update |
| `993` | Deletion error | Data validation failed on delete |
| `994` | Overlapped data | Duplicate record, Kayko treats this as already accepted for some retries |
| `995` | No downloaded file | File not found on server |
| `999` | Unknown error | Contact RRA administrator |

## Error handling pattern

Successful mapped routes return `{ message, data }`. VSDC failures throw HTTP errors with:

```json
{ "status": "910", "message": "…", "date": "20260820184713" }
```

```javascript
function handleEbmError(body) {
  const { status, message } = body;
  const retryable = ['894', '896', '999'];
  const userFixable = ['881', '882', '884', '910', '921', '922', '994'];

  return {
    success: false,
    code: status,
    message,
    retryable: retryable.includes(status),
    userFixable: userFixable.includes(status),
  };
}
```

```php
<?php
function handleEbmError(array $body): never {
    $code = $body['status'] ?? '999';
    throw new EbmException($code, $body['message'] ?? 'Unknown error');
}
```

The retryable VSDC codes are `894`, `896`, and `999`. Treat `994` as already accepted when retrying a signed request.

## Version history

Codes `881`–`884` were added in **v1.0.5** (May 2023) related to the new `prcOrdCd` (purchase order code) field.
