Switch to the **API Playground** tab and pick an endpoint from the sidebar. Each page has a pre-filled request body, auth headers, and a **Send** button.

## Before you start

<Steps>
  <Step title="Pick an environment">
    Use the **environment dropdown** on any playground page. Default: `http://localhost:3000/ebm`. Code samples use `{{baseUrl}}` and update when you switch.
  </Step>
  <Step title="Authenticate">
    | Routes | Header |
    |--------|--------|
    | Customers, constants, branches, notices, … | `Authorization: Bearer sk_…` or `x-api-key: sk_…` |
    | Initialization (`/initialize/*`) | Prefer `X-API-Token`; a business API key also works |

    See [API Keys](/concepts/api-keys) for business key setup.
  </Step>
  <Step title="Set tenant headers on proxied routes">
    Send `x-tin` and `x-branch-id` on customer, branch, notice, and device-init calls. Branch select and notices also need `x-last-request-date` (`YYYYMMDDHHmmss`). You do not send `ebm_url` in the body.
  </Step>
  <Step title="Send">
    Edit the pre-filled body or query, click **Send**, and inspect the response panel.
  </Step>
</Steps>

## Response shapes

| Kind | Shape |
|------|-------|
| Device init | `{ resultCd, resultMsg, resultDt, data }` |
| Many proxied routes | Unwrapped `data` |
| `/constants/*`, notices, save user | `{ message, data }` |
| Auth failures | `{ status, message, error }` |

`resultCd: "000"` = success. Full code list: [Response Codes](/reference/response-codes).

For field-level docs and workflow guides, see the matching page under **API** in the sidebar (for example [Sales](/api/sales)).

<Note>
  The Mintlify cloud preview may not reach `localhost`. If playground calls fail, test from your machine with cURL or Postman using the same URL and payload.
</Note>
